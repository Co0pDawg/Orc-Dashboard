# Time Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Time page to the Orchestration Board with Day, Week and Month tabs, Work Detail-shaped entries and a per-day scrum summary. The data comes from Cooper's worklog hooks through a scheduled sync.

**Architecture:**
- The worklog repo gains an export of a day's re-ticketed events (no prompt text) and a sync script that uploads `timeline/<date>` to the board db through a headless `claude -p`.
- The board page gains a Time view whose pure modules turn those events, plus the board's own sessions and cards, into driving segments, agent spans, entries and a scrum summary. String renderers and one controller draw them in both skins.

**Tech Stack:**
- Board: vanilla ES modules, `node:test`, no dependencies (see `STANDARDS.md`).
- Worklog: PowerShell 7 for the sync, PowerShell 5.1 for the hooks (unchanged); its own `test.ps1`.
- Upload: `claude -p --model haiku --allowedTools ToolSearch ArtifactData`.
  - Verified 2026-10-20: a headless run reads the board db with no prompt.

**Spec:** `docs/2026-10-20-time-site-design.md` (approved by Cooper 2026-10-20). Read it before any task.

**Plan refinement of the spec, Fable's call:**
- The sync uploads the day's re-ticketed **events**, not precomputed segments. The page computes driving segments in `js/time/segments.js`.
  - Why: one tested language for the rule, and the 15-minute tail can change without re-syncing.
- The `timeline` doc shape is therefore:
  ```
  {date, synced, tz, events:[{at, kind, session, ticket}], sessions:{id:{project, review}}, notes:{ticket:text}, flags:{ticket:{unplanned:true}}}
  ```
- Agent markers are simply the `agent` events.
- Update the spec's Data section to match in Task 8.

## Global Constraints

**Privacy and the worklog:**
- No prompt text, or anything Cooper typed, leaves the machine. The upload carries only `at, kind, session, ticket`, `project`, `review`, `notes` and `flags`.
- `worklog.ps1` printed output and `<date>.txt` stay byte-identical when the new switch is absent.
- The worklog repo has uncommitted work by Cooper: change only the files a task names, never commit, stage, stash or revert there.

**Entries:**
- Entries never overlap. A day's entries plus "Not entered" minutes equal the driven total within one rounding unit per entry.
- An entry is at most 120 minutes (portal maximum).
- Rounding options are Exact (1 min), 5, 10, 15 and 30 minutes; the default is 15. Views always show exact minutes.
- Driving: from a `prompt` through that turn's `stop`, then up to 15 minutes more. It is cut short by a `prompt` in a different session.
- Ticket with no `PET-NNNNN` (`UNKNOWN`, `PR-NNNN`, dropped `-`, empty) becomes `null`, shown as "No ticket" and entered with an empty Ticket field plus a "needs a ticket" flag.

**Sync:**
- The sync never calls a model except the one upload call. It skips the upload when its inputs are unchanged (day CSV, `sessions.map`, `<date>.map`, `<date>.txt`).

**Page:**
- Hash tokens: `#time` (Day), `#time-week`, `#time-month`; Board is `#board` or no hash. The artifact passes only plain `[A-Za-z0-9._~-]` tokens.
- It follows `STANDARDS.md`:
  - pure modules have no DOM and no storage;
  - render modules build strings only;
  - `prefs.js` is the only storage module;
  - every db value goes through `esc()`;
  - colors come from tokens only;
  - skin rules live in `sleek.css` and `leet.css`.
- Commits in the board repo are Fable's, after review. Builders leave changes unstaged.

## Review Focus

1. **Overnight work:** a session prompted before midnight is in the previous day's CSV. A day's segments must start no earlier than 00:00 and end no later than 23:59:59 of that day, and must not borrow events from another day. Test in Task 3.
2. **A turn with no `stop`** (crash, or still running now): the segment ends at that session's last event plus 15 minutes, or at "now" for today, whichever is earlier. Test in Task 3.
3. **A day with no data, or only `notify` events:** the views show an empty state, entries are empty, and the scrum list says "Nothing logged". Tests in Tasks 4 and 5; empty-state render in Task 6.
4. **Timeline doc missing** because the sync has not run: Day, Week and Month say "No time synced for <date> yet" and name `sync-timeline.ps1 -Date <date>`. Render test in Task 6.
5. **Ticket spellings:** `PET-17619`, `PET-17619*`, `17619`, `#17619`, `UNKNOWN`, `PR-6243` and `-` must normalize the same way on timeline events and board cards, so columns and scrum lines join. Test in Task 3.
